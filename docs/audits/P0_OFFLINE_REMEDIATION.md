## 보고서와 대조한 사항

- NAT05: 부분문자열 분류 문제는 확인했지만, `RuntimeError("Calculation syntax error")` 예시는 클래스 이름이 `str(error)`에 포함되지 않아 성립하지 않습니다.
- NAT06: 오류 응답 계약 문제는 수정했습니다. 기존 FastMCP가 예외를 잡으므로 프로세스 전체가 반드시 종료된다는 주장은 확인되지 않았습니다.
- SEC04: 콜백은 실행 중인 `_pump` 프레임에서 참조됩니다. 즉시 GC된다는 주장 대신 실제 초기화 실패 정리 누락을 수정했습니다.
- CALC04: 현재 `Capstone`에는 `click`과 `type_text`가 있습니다.
- CAP06: 제공 파일에서 저장된 런 이름을 정상 복원합니다. 전체 유실 주장과 맞지 않습니다.
- CAP14: 부모 맵 생성은 O(N)입니다. CAP15의 부모 없는 데이터셋은 이미 명시적으로 거부합니다.
- CAP01/02: Python ZIP 파서는 헤더 크기로 출력을 제한하고 파일을 디스크에 추출하지 않습니다. 보고서의 ZipSlip/ADS 시나리오를 그대로 확정할 수 없습니다.
- TEL01/02/03/04/08 일부는 현재 코드에 없는 256채널 제한, 정렬, 상대 시간 변환, 기존 전역 락을 전제로 합니다.
- P0-NUM02: 기존 보고서 경로는 비양수 값을 로그에 넘기기보다 일반 선형 회귀로 대체했습니다. 이 잘못된 모델 대체를 차단했습니다.

- 51개 장치 RPC, 하드웨어 클록 동기화, 고속 스트리밍은 추측 구현하지 않았습니다.
- 이중 슬릿 포락선 알고리즘, 광학 포화·노이즈 강건성은 미구현/미검증입니다. 잘못된 기본 결과 반환만 차단했습니다.
- 로컬 디버그 포트 인증과 파일 접근의 워크스페이스 정책 전체는 이번 변경에 포함하지 않았습니다.
- 에픽 #123~#130은 부분 수정이므로 자동 종료하지 않습니다. PR 병합도 수행하지 않습니다.

## 재현 가능한 검증

의존성은 `uv sync --frozen`, 검사는 `uv run --no-sync ruff check src tests`, `uv run --no-sync basedpyright src`, `uv run --no-sync pytest`를 사용합니다.

`CAPSTONE_GOLDEN_MASTER_DIR`에 로컬 실험 폴더를 지정하면 실제 파일 테스트가 실행됩니다. 원본 파일은 Git 또는 PR에 포함하지 않습니다. 코퍼스 테스트는 각 파일의 SHA-256을 전후 비교합니다.

`CAPSTONE_RUN_LIVE_TESTS=1`을 명시하지 않으면 라이브 테스트는 실행하지 않습니다. 이 검증에서는 값을 0으로 설정했습니다.

통합 작업 브랜치 검증 결과: Windows Python 3.12에서 **705 passed, 7 skipped**, 전체 Ruff 및 Basedpyright 통과. 7개 제외는 명시적 라이브 테스트 5개와 설정 전용 자이로스코프의 측정 전용 테스트 2개입니다. 이 수치는 아래 수정 묶음을 모두 합친 상태의 로컬 결과이며, 개별 PR은 각각 원격 CI로 검증합니다.
